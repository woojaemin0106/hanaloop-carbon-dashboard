## 2026-05-17 - PCF 계산 로직 구현

### 자동 검증

- `npm run build` 통과
- `npm run lint` 통과
- `npm run test` 통과
  - 총 5개 테스트 통과
  - PCF 계산 테스트 4개 통과
  - 앱 진입점 smoke 테스트 1개 통과

### 수기 검산

- 전기 활동량 합계: 1,029 kWh
  - 계산식: `1,029 x 0.456 = 469.224 kgCO2e`
- 원소재 플라스틱 1 활동량 합계: 3,186 kg
  - 계산식: `3,186 x 2.3 = 7,327.8 kgCO2e`
- 원소재 플라스틱 2 활동량 합계: 106 kg
  - 계산식: `106 x 3.2 = 339.2 kgCO2e`
- 운송 활동량 합계: 839 ton-km
  - 계산식: `839 x 3.5 = 2,936.5 kgCO2e`
- 총 배출량: `469.224 + 7,327.8 + 339.2 + 2,936.5 = 11,072.724 kgCO2e`
- Scope 2 총량: `469.224 kgCO2e`
- Scope 3 총량: `10,603.5 kgCO2e`
- 2025년 5월 중복 행 합산 결과: `2,210.076 kgCO2e`

### 구현 검토

- 배출계수는 활동 유형과 라벨이 모두 일치해야 매칭되도록 했다.
- 배출계수 `validFrom`이 활동일보다 늦으면 사용할 수 없도록 했다.
- `factorVersion` 옵션을 두어 특정 버전의 배출계수로 재계산할 수 있게 했다.
- 활동량이 음수이거나 생산수량이 0 이하이면 오류를 던지도록 했다.
- 월별 집계는 같은 월의 중복 행을 합산하도록 했다.
- Playwright 기본 테스트에서 dev 서버 자동 실행을 제거했다. Windows 환경에서 Next dev 서버가 종료되지 않아 테스트 명령이 타임아웃되었고, 현 단계의 검증 대상은 계산 로직이므로 서버 의존 없는 테스트로 분리했다.
- ESLint 설정은 Next 16의 flat config export를 직접 사용하도록 수정했다. 기존 `FlatCompat` 방식은 순환 구조 오류로 `npm run lint`가 실패했다.

### 다음 검토 포인트

- 내부 API 또는 조회 계층에서 계산 결과가 그대로 노출되는지 확인한다.
- UI에서 총량, 월별, Scope별 값의 단위가 `kgCO2e`, `tCO2e`로 혼동 없이 표시되는지 확인한다.

## 2026-05-18 - 생산수량 입력 및 검증 UX 구현

### 자동 검증

- `npm run lint` 통과
- `npm run test` 통과
  - 총 9개 테스트 통과
  - 기존 PCF 계산/API 테스트 유지
  - 생산수량 입력 검증 테스트 추가
  - 앱 진입점 smoke 테스트를 생산수량 입력 폼 연결 기준으로 갱신
- `npm run build` 통과

### 브라우저 검토

- `http://127.0.0.1:3001`에서 실제 입력 상호작용을 확인했다.
- 생산수량 `10` 입력 시 제품 단위 PCF가 `1,107.272 kgCO2e/과제 데이터 묶음`으로 재계산되는지 확인했다.
- 같은 입력에서 기본 생산수량 1개 기준 대비 변화율이 `-90%`로 표시되는지 확인했다.
- 생산수량 `0` 입력 시 `생산수량은 0보다 커야 합니다.` 오류 메시지가 노출되는지 확인했다.

### 수기 검토

- 생산수량 입력은 총 배출량을 바꾸지 않고 `pcfKgCO2ePerUnit`만 재계산하도록 제한했다. 활동량 편집과 생산수량 기반 단위 환산을 분리하기 위한 설계다.
- 빈 값, 숫자가 아닌 값, 0 이하 값은 각각 한국어 오류 메시지를 반환하도록 확인했다.
- 숫자가 아닌 입력은 `Number.isFinite`로 먼저 걸러 라이브러리 기본 오류 문구가 화면에 노출되지 않게 했다.
- 입력 필드에는 `aria-invalid`, `aria-describedby`를 연결하고, 결과/오류 영역에는 `aria-live`를 사용했다.
- KPI 단위는 `summary.product.productionUnit`을 기준으로 구성해 README, API, 화면의 단위가 서로 어긋나지 않게 했다.
- Playwright 검증 스크립트에서 한글 라벨 셀렉터가 셸 인코딩 영향으로 깨질 수 있어, 최종 브라우저 상호작용 검증은 안정적인 `id` 셀렉터와 메시지 텍스트로 확인했다.
