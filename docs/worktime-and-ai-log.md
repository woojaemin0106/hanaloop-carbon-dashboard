# 작업 소요 시간 및 AI 활용 기록

이 문서는 최종 README와 발표 준비를 위해 작업 시간, 시간이 많이 소요된 부분, AI 활용 방식, 사용 프롬프트, 의사결정 이유를 누적 기록합니다.

## 기록 원칙

- 작업 시간은 커밋 시각, 검증 로그, 실제 진행 내용을 기준으로 보수적으로 기록한다.
- 최종 제출 전 실제 총 작업 시간을 다시 합산해 README에 반영한다.
- AI 활용 내역은 `AI가 도운 일`과 `지원자가 판단한 일`을 분리해 기록한다.
- 발표에서는 AI 사용 자체보다 `왜 그렇게 판단했는지`, `생성 결과를 어떻게 검토했는지`를 중심으로 설명한다.

## GitHub 작업 규칙

- 모든 작업은 `main`에서 새 브랜치를 만들어 진행한다.
- 파일 하나를 수정한 뒤 해당 파일을 재검토하고 커밋한다.
- 마지막 파일 작업 후 전체 재검토와 수기 검토를 진행한다.
- PR 제목은 항상 `FEAT : 작업 내용` 형식으로 작성한다.
- PR 머지 후 원격 작업 브랜치를 삭제한다.
- 로컬 `main`은 원격 `main`과 다시 동기화한 뒤 다음 작업을 시작한다.

## 발표용 핵심 문장 초안

- AI는 요구사항 정리, 누락 항목 점검, 검증 체크리스트 작성에 보조적으로 활용했습니다.
- 핵심 설계 판단은 직접 했고, 특히 활동 데이터와 배출계수를 분리한 이유는 실제 탄소 관리 플랫폼에서 계수 버전 이력 추적이 중요하기 때문입니다.
- 전기 데이터는 구매 전력으로 보아 Scope 2에 매핑했고, 원소재와 운송은 공급망 활동이므로 Scope 3에 매핑했습니다.
- 작업은 파일별 재검토와 커밋, 전체 재검토와 PR 머지 흐름으로 관리했습니다. 이는 과제에서 커밋 히스토리와 설명력을 요구했기 때문입니다.
